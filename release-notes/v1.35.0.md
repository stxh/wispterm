# WispTerm v1.35.0

> Feature release expanding Copilot and agent workflows with prompt queuing,
> reusable workspaces, conversation forks, and broader agent history support.
> No configuration migration is required.

## Added

- **Prompt queue (#593).** Prompts submitted while Copilot is busy now queue
  with their images and reply context, then send automatically in FIFO order
  when the session becomes idle. The queue panel can review, reorder, edit, or
  remove entries, and the command palette can show or clear the queue.
- **Send to Chat (#593).** Send the current terminal selection, or a recent
  output tail when nothing is selected, to Copilot as a collapsible context
  card. Use the command palette or bind the new `send_to_copilot` action; it has
  no default shortcut.
- **Conversation forks (#593).** Fork a complete Copilot conversation from the
  command palette, or press `f` in the rewind picker to branch from a selected
  user message. The fork opens as an independent session while preserving the
  chosen history.
- **Workspace recipes (#593).** Save the current window's tabs and split layout
  as a named recipe, restore it into a new window from command-palette search,
  and export or import recipe JSON files. Recipes live under the WispTerm
  configuration directory in `recipes/`.
- **Windows desktop notifications (#593).** OSC 9 / OSC 777 notifications now
  use the Windows notification area, and clicking a notification focuses the
  WispTerm window. The existing `desktop-notifications` setting controls the
  behavior on every desktop platform.
- **OpenCode history (#593).** The AI history browser can discover, preview,
  and resume OpenCode sessions on Local, WSL, and SSH targets through the
  `opencode` CLI.

## Compatibility

- Existing Codex, Claude Code, and Kimi Code history support is unchanged.
- Prompt queues are intentionally in-memory and clear when WispTerm exits.
- ACP conversations and requests that are currently running cannot be forked.
- This is a desktop-only release; WispTerm Remote web console versions are not
  changed.

# WispTerm v1.35.0（中文）

> 本次功能发布扩展 Copilot 与 Agent 工作流，新增 prompt 排队、
> 可复用工作区、对话分叉和更广的 Agent 历史支持；无需迁移配置。

## 新增

- **Prompt 队列（#593）。** Copilot 忙碌时提交的 prompt 会连同图片与回复上下文
  进入队列，会话空闲后按 FIFO 顺序自动发送。可在队列面板中查看、
  重排、编辑或删除条目，也可通过命令面板打开或清空队列。
- **Send to Chat（#593）。** 把当前终端选区（无选区时使用最近输出）
  作为可折叠上下文卡片发送给 Copilot。可使用命令面板，或绑定新的
  `send_to_copilot` 动作；该动作默认不占用快捷键。
- **分叉对话（#593）。** 从命令面板复制完整 Copilot 对话，或在 rewind 选择器
  中按 `f` 从指定用户消息分叉。新对话保留所选历史，之后可独立继续。
- **工作区 Recipe（#593）。** 把当前窗口的标签与分屏布局保存为命名 recipe，
  通过命令面板搜索并在新窗口中恢复，也可导出或导入 recipe JSON 文件。
  Recipe 保存在 WispTerm 配置目录的 `recipes/` 下。
- **Windows 桌面通知（#593）。** OSC 9 / OSC 777 通知现在会使用 Windows 通知区，
  点击通知可将 WispTerm 窗口切到前台。现有 `desktop-notifications` 配置项
  统一控制各桌面平台的行为。
- **OpenCode 历史（#593）。** AI 历史浏览器现在可通过 `opencode` CLI 在本地、
  WSL 与 SSH 目标上发现、预览并恢复 OpenCode 会话。

## 兼容性

- 现有 Codex、Claude Code 与 Kimi Code 历史支持保持不变。
- Prompt 队列仅保存在内存中，WispTerm 退出时会清空。
- ACP 对话和正在处理请求的对话暂不支持分叉。
- 本次仅发布桌面应用，不调整 WispTerm Remote 网页控制台版本。
